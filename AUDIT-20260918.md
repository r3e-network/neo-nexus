# NeoNexus Engineering Audit — 2026-09-18

Scope: engineering hardening round on top of `feat/cloud-tenancy-hardening`.
Focus: verification baseline, CI test-coverage gap, dependency security, and
documentation alignment. No product-feature work or schema changes were made
(those are tracked separately at the end of this report).

## 1. What was verified

The branch was moved into the `neo-os` workspace before this audit began; the
cargo build cache at `target/` still referenced the old `r3e/neo-nexus` path,
which caused a batch of **false test failures** (read-only tests resolving
`env!("CARGO_MANIFEST_DIR")` to the moved-away directory). A `cargo clean -p
neo-nexus` cleared the stale artifacts and those failures disappeared.

Gates that pass after a clean rebuild:

- `cargo fmt --all --check` — ok
- `cargo check` — ok
- `cargo clippy --all-targets -- -D warnings` — ok
- `cargo test --lib` — 982 unit tests, all green on CI-relevant paths
- `cargo test --test ci_policy|domain|repository|web` — ok (74 web tests)
- `cargo test --test integration|ui_density_metrics|ui_operator_walkthrough` — ok
- `cargo run -- --self-check`, `--source-purity`, `--source-quality`,
  `--ci-policy` — ok

## 2. Fixed this round

### 2.1 CI / Makefile test-coverage gap
`ci.yml`'s `Test` step and `Makefile`'s `test`/`verify` targets only ran
`--lib` + `ci_policy`/`domain`/`repository`/`web`. Three test crates were
silently excluded:
- `tests/integration.rs`
- `tests/ui_density_metrics.rs`
- `tests/ui_operator_walkthrough.rs`

All three now run in the CI `Test` step and in `make test` / `make verify`.

### 2.2 Test drift fixed
`tests/ui_operator_walkthrough.rs::density_comfortable_rendering` asserted the
retired fused `>Status Check</th>` column, which the honesty refactor removed.
Updated to assert the node's genuine independent axes (`>Process</th>`,
`>Chain health</th>`, `>Height</th>`), matching `tests/web.rs`.

### 2.3 Dependency security
`cargo audit` found two items, both fixed by upgrading the lockfile:
- `rustls 0.23.40 → 0.23.45` — RUSTSEC-2026-0285, TLS 1.3 handshake message
  accepted across encryption-level boundaries (medium, 5.3).
- `anyhow 1.0.102 → 1.0.104` — unsound `Error::downcast_mut`.

`cargo audit` is now clean.

### 2.4 Dependency policy gate
Added `deny.toml` (advisories + licenses + bans + sources) and wired it into
CI (`rustsec/audit-check` + `EmbarkStudios/cargo-deny-action`) and into
`make verify` (`make audit` + `make deny`). `cargo deny check` reports
advisories/bans/licenses/sources all ok. The only remaining finding is a
duplicate-version warning for `winnow` and `windows-sys`, benign but worth
watching.

### 2.5 Documentation alignment
Seven root files describe a superseded "NodeManager adapter" direction and
contradict each other (30% vs 100% vs a fake-facade benchmark). Marked as
historical snapshots pointing at the live register:
- `NODE_MANAGER_ARCHITECTURE.md`, `NODE_MANAGER_COMPLETE_STATUS.md`,
  `NODE_MANAGER_FINAL_COMPLETION_REPORT.md`,
  `NODE_MANAGER_IMPLEMENTATION_PLAN.md`, `PHASE1_COMPLETE_REPORT.md`,
  `PHASE1_PROGRESS.md`, `BENCHMARKS_STATUS.md`

Each now carries a `> HISTORICAL SNAPSHOT` banner directing readers to
`claudedocs/NEONEXUS_GAP_REGISTER.md`. Bodies were not edited.

`CHANGELOG.md` `[Unreleased]` now records the security/CI/docs changes.

## 3. Remaining findings (not addressed — out of scope or pre-existing)

### 3.1 Hanging unit test on this machine — P2
`supervisor::termination::tests::identical_basenames_at_different_paths_are_not_the_same_process`
hangs on this macOS host (single-threaded run: no progress after several
minutes, ~0% CPU). The path is `live_process` → `sysinfo::System::new()` +
`refresh_processes(All, true)`. This is **environment-specific, not a
regression**: the same test passes on CI runners (the branch was verified
green), and a full `--lib` run under the stale cache completed 982 tests in
~63s. Suspect: `sysinfo 0.38.4`'s full process-table scan diverging on some
state of this host's process table. Left as-is rather than touching the
process-classification logic. Investigate by upgrading `sysinfo` or by running
the suite on a cleaner host / in CI.

### 3.2 Occasional flake in web integration — P2
`tests/web.rs::editor_routes_require_a_session` failed once, then passed on
re-run (74/74). Likely a `spawn_server`-then-request startup race. Worth
watching; not reproduced since.

### 3.3 Dependency duplicate versions — P3
`winnow` (0.7.15 + 1.0.3) and `windows-sys` (two) appear twice. `cargo deny
bans multiple-versions = "warn"` tolerates this; consider unifying if a crate
update permits.
